# 第1阶段：项目初始化与基础规范

## 1. 阶段目标

本阶段只建立一个可以编译、测试、打包和启动的 Spring Boot Maven 项目，不实现业务接口。

完成后应具备：

- Java 17 与 Spring Boot 3.5.16 基础工程。
- Maven Wrapper，避免依赖开发者机器上的 Maven 版本。
- 标准源码、资源和测试目录。
- 后续分层所需的包目录。
- 一个只验证 Spring 容器能启动的测试。
- 一个可以直接运行的可执行 JAR。

本阶段明确不做：

- 不连接 MySQL、Redis 或 RabbitMQ。
- 不创建 Controller、Service、Mapper、Entity。
- 不添加业务接口。
- 不为了测试启动而创建临时的 `/hello` 接口。

## 4. 分层职责边界

当前阶段各业务包保持为空，但必须先明确后续职责。

| 层 | 目录 | 只负责什么 | 不应该负责什么 |
| --- | --- | --- | --- |
| 接口层 | `controller` | 接收 HTTP 参数、调用 Service、返回响应 | 不写 SQL，不直接操作 Mapper，不实现业务规则 |
| 业务层 | `service` | 业务校验、事务编排、状态变化 | 不处理 HTTP 对象，不拼接响应页面 |
| 数据访问层 | `mapper` | 执行数据库查询和更新 | 不判断活动能否售票，不决定订单状态 |
| 配置层 | `config` | 注册框架 Bean、序列化器、拦截器、客户端配置 | 不存放业务流程 |
| 数据模型 | `entity` | 对应数据库表结构 | 不作为所有接口的输入输出对象 |
| 请求模型 | `dto` | 接收和校验接口输入 | 不直接持久化 |
| 响应模型 | `vo` | 面向调用方展示数据 | 不承担数据库映射职责 |
| 公共能力 | `common` | 统一响应、常量等真正通用内容 | 不堆放无法分类的业务代码 |
| 异常层 | `exception` | 业务异常与统一异常转换 | 不吞掉异常 |

后续调用方向固定为：

```text
HTTP请求
   ↓
Controller 接口层
   ↓
Service 业务层
   ↓
Mapper 数据访问层
   ↓
MySQL
```

禁止出现反向调用：

```text
Mapper → Service        错误
Service → Controller    错误
Entity → Mapper         错误
```

## 5. Maven依赖

本阶段只保留：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
```

原因：

- `spring-boot-starter-web` 提供 Spring MVC 和内嵌 Tomcat，让项目具备后续开发 HTTP 接口的基础。
- `spring-boot-starter-test` 提供 JUnit 5、Spring Test 等测试能力。
- 数据库、Redis、Redisson、RabbitMQ必须在使用它们的阶段再加入，避免项目在没有外部环境时无法启动。

## 6. 启动类

文件：

```text
src/main/java/com/example/flashticket/FlashTicketApplication.java
```

职责只有一个：启动 Spring Boot。

```java
@SpringBootApplication
public class FlashTicketApplication {

    public static void main(String[] args) {
        SpringApplication.run(FlashTicketApplication.class, args);
    }
}
```

`@SpringBootApplication` 会以当前包为根进行组件扫描，因此启动类必须放在 `com.example.flashticket` 根包，后续的 Controller、Service 和配置类都放在它的子包中。

## 8. 实现步骤

### 步骤1：确认Java版本

```powershell
java -version
```

应输出 Java 17。

### 步骤2：确认Maven Wrapper

```powershell
.\mvnw.cmd -version
```

必须使用项目内的 Wrapper，不要使用机器上的旧版 `mvn`。

### 步骤3：运行上下文测试

```powershell
.\mvnw.cmd clean test
```

`contextLoads()` 不验证业务，只验证：

- 配置文件能够解析。
- Spring 容器能够创建。
- 自动配置没有冲突。
- 启动类能够被测试找到。

### 步骤4：打包

```powershell
.\mvnw.cmd clean package
```

成功后生成：

```text
target/flash-ticket-0.0.1-SNAPSHOT.jar
```

### 步骤5：启动JAR

```powershell
java -jar target\flash-ticket-0.0.1-SNAPSHOT.jar
```

日志中应出现：

```text
Tomcat started on port 8080
Started FlashTicketApplication
```

### 步骤6：验证HTTP服务器

访问根路径时返回404属于正确结果，因为本阶段没有Controller：

```powershell
Invoke-WebRequest http://localhost:8080 -SkipHttpErrorCheck
```

不要通过增加无意义接口消除这个404。

## 9. 接口实现顺序

本阶段没有业务接口。验收顺序替代为：

```text
上下文测试通过
→ Maven打包通过
→ JAR启动成功
→ 8080端口能够响应HTTP
→ 停止验证进程
```

必须完成全部基础验证后，才能进入数据库阶段。

## 10. 常见问题

### 端口被占用

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8080
```

确认进程确实是自己的测试服务后再停止：

```powershell
Stop-Process -Id <PID>
```

### 使用全局Maven失败

不要运行：

```powershell
mvn clean package
```

统一运行：

```powershell
.\mvnw.cmd clean package
```
